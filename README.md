# AccessMetrics

**An interactive prototype for accessible product experiences and simulated accessibility analytics.**

AccessMetrics demonstrates how accessibility controls, user experience signals, and an analytics dashboard could work together in a product workflow. The project is designed as a portfolio prototype rather than a production analytics platform: the dashboard metrics are generated by a transparent simulation model, not collected from real users.

## Demo

The application contains three main experiences:

- **Landing page** — introduces the concept and links to the interactive experiences.
- **Accessibility demo** — an example learning interface with persistent accessibility preferences, text-to-speech, captions, transcript controls, and a custom video player.
- **Analytics dashboard** — explores simulated conversion, retention, cohort, and revenue effects using adjustable assumptions.

## Key features

### Accessibility experience

- High-contrast mode
- Simplified layout
- Adjustable text size from 90% to 150%
- Browser text-to-speech
- Optional captions and transcript
- Keyboard-accessible custom video controls
- Accessibility preferences persisted locally with `localStorage`

### Analytics prototype

- Interactive user-base simulator
- Transparent conversion and retention assumptions
- Simulated revenue attribution
- Accessibility vs. standard-user comparison chart
- Explicit labelling of simulated rather than empirical metrics

## Simulation methodology

The dashboard intentionally uses synthetic assumptions so the application can demonstrate the analytics workflow without claiming access to production customer data.

The current assumptions are defined in `src/utils/MetricsSimulator.ts`:

| Assumption | Value |
|---|---:|
| Accessibility adoption | 22% |
| Simulated conversion uplift | 12.4% |
| Simulated retention uplift | 8.1% |
| Revenue per additional conversion | $85 |

The simulator derives cohort size, additional conversions, retained users, and attributed revenue from these inputs. These values are **illustrative only** and should not be interpreted as measured business outcomes.

The application uses React Context for accessibility preferences and a small deterministic simulation utility for the dashboard. There is no backend, authentication system, production analytics pipeline, or external database in this prototype.

## Local media

The video player uses an original, locally generated demonstration video stored in `public/media/accessibility-demo.mp4` with a matching WebVTT caption file.

The media was created specifically for this project and contains no third-party footage, music, or voice recording. See `public/media/README.md` for the asset provenance and reuse note.

## Testing

The test suite currently covers the two most important pieces of application logic:

- accessibility preference persistence and recovery
- deterministic metric calculations and input validation

The browser-dependent features such as speech synthesis and video playback should additionally be checked manually in a modern browser because their runtime APIs are not fully represented by the unit-test environment.

## Development notes

This project was initially prototyped with Lovable and was subsequently reviewed and refined as a standalone React/TypeScript project. The current repository removes the original platform-specific development tooling and focuses on the application's reusable source code, tests, local media, and documentation.

The project is intentionally presented as a prototype. Claims about accessibility impact, conversion, retention, revenue, compliance, or SDK functionality should not be treated as validated production capabilities.

## Project status

**Portfolio prototype — functional front-end demonstration.**

Future work could include a real event-ingestion API, authenticated product analytics, experiment design, validated causal measurement, automated accessibility auditing, and production-grade report generation.
